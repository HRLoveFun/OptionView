# 维度 2：安全性检查清单

按项目类型侧重检查。所有项目通用项前置，各技术栈专项在后。

## 2.1 通用（所有项目）

### 注入类
- [ ] SQL 注入：字符串拼接构造 SQL（应使用参数化查询 / ORM）；
- [ ] 命令注入：`exec`/`system`/`subprocess shell=True`/`os.system` 拼接用户输入；
- [ ] 路径遍历：文件路径由用户输入构成且未校验/未约束在白名单目录内（`../` 逃逸）；
- [ ] 模板/表达式注入：将用户输入传入模板引擎、`eval`、`Function`、反序列化器。

### 敏感信息
- [ ] 硬编码密钥：API key、密码、token、连接串写入代码或配置文件且已提交；
- [ ] 日志泄露：日志打印密码、token、完整身份证/手机号、请求体中的敏感字段；
- [ ] 错误信息泄露：异常堆栈、SQL 语句、内部路径直接返回给客户端；
- [ ] `.gitignore` 是否覆盖 `.env`、密钥文件、数据文件。

### 权限控制
- [ ] 接口/路由是否校验身份与授权（水平越权：用户 A 访问用户 B 的资源）；
- [ ] 管理端接口是否有独立权限门槛；
- [ ] CORS 配置是否过宽（`*` 搭配凭证）；
- [ ] 前端权限仅是"隐藏 UI"而后端无校验。

### 依赖
- [ ] 已知漏洞依赖：命令化审计由 SKILL.md「第二步：依赖安全审计」强制执行，此处仅补充静态检查——依赖声明中的通配符版本（`*`、`latest`）、lockfile 是否提交；
- [ ] 依赖版本是否锁定（lockfile 是否提交）；
- [ ] 是否引入了来源可疑、长期未维护的依赖。

## 2.2 前端专项

- [ ] XSS：`dangerouslySetInnerHTML`/`v-html`/`innerHTML` 渲染未净化的用户内容；
- [ ] 敏感数据存入 `localStorage`（token 优先考虑 httpOnly cookie）；
- [ ] `postMessage` 未校验 origin；
- [ ] 打包产物中包含 sourcemap 或调试密钥发布到生产；
- [ ] URL 中传递敏感参数（token、身份证号出现在 query string）。

## 2.3 后端专项

- [ ] 认证会话：token 生成随机性、过期策略、刷新机制；
- [ ] 密码存储：是否使用 bcrypt/argon2 等慢哈希，禁止 MD5/SHA1 明文可比对存储；
- [ ] 速率限制：登录、发码、导出等易被滥用的接口是否有限流；
- [ ] 文件上传：类型/大小校验、存储位置不可执行、文件名不可控；
- [ ] SSRF：服务端按用户提供的 URL 发起请求且未限制目标；
- [ ] 数据库账号权限是否最小化（如只读场景使用只读连接）。

## 2.4 基础设施专项

- [ ] Dockerfile：是否以 root 运行、是否 COPY 了密钥/`.env`、基础镜像是否固定摘要；
- [ ] CI/CD：secrets 是否走平台密钥管理而非明文变量；日志是否回显 secrets；
- [ ] IaC：安全组/防火墙是否对公网开放了过宽端口；存储桶是否公开可读写；
- [ ] 生产配置中的默认口令、调试模式开关。

## 判定原则

- 漏洞利用可行性 > 理论风险：仅在输入确实可控时才报注入类 P0；
- 密钥已提交到版本库的一律 P0（即使已轮换，也应提示清理历史）；
- 无法确认输入来源是否可控时，标注为"待确认疑点"而非直接定级。
